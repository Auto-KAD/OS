Kernel Architecture Comparison

Compare the structural and operational characteristics of the two designs.

Monolithic Kernel vs Microkernel

Both architectures provide mechanisms for operating-system functionality, but they organize services differently. A monolithic design places many services in kernel space, while a microkernel keeps the kernel core smaller and commonly moves many services into user space.

Feature Monolithic Kernel Microkernel
Kernel Size Generally larger Smaller core
OS Services Many services run in kernel space Many services can run in user space
Communication System calls and direct kernel-component interaction Message passing and IPC
Device Drivers Commonly kernel-space Can be user-space servers
File System Commonly part of kernel Can operate as a user-space server
Fault Isolation Less isolation between many kernel components Greater isolation for user-space services
IPC Not the primary mechanism between kernel components Important mechanism for communication between services
Performance Consideration Direct kernel interactions can reduce communication overhead IPC and context switches can introduce overhead
Modularity Can support modular components and loadable modules Services are naturally separated into components
Example Linux MINIX 3, seL4

Structure

The primary architectural difference is where operating-system services execute.

  • Monolithic → many services in kernel space
  • Microkernel → small kernel core
  • Microkernel → many services in user space

Communication

Microkernel architectures commonly rely heavily on IPC and message passing because services are separated into processes.

  • System calls
  • IPC
  • Message passing

Fault Isolation

Separating services into user-space processes can limit the effect of a failure in one service.

  • Service separation
  • Smaller privileged core
  • Service restart possibilities

Linux in This Case Study

Linux is generally described as using a monolithic kernel architecture while also supporting modularity through mechanisms such as loadable kernel modules. This means that Linux is not a simple "everything is permanently built into one block" design. Many kernel functions execute with kernel privileges, while modules provide flexibility.
